# Avoid generic output with observable rules

“AI slop” describes an outcome, not a formal design standard. Convert it to inspectable defects. Familiar software conventions are not inherently poor taste.

| Failure | Problem | Correction | Evidence |
| --- | --- | --- | --- |
| Identical cards everywhere | Hierarchy disappears | Group by task; dominant list and quieter sections | Main task precedes summaries |
| Giant welcome hero | Pushes work below fold | Compact identity and next action | Useful rows visible |
| Arbitrary KPI quartet | Metrics become filler | Keep decision-relevant metrics; permit zero | Definition, scope, next action |
| Floating search | Unclear scope | Attach record search to toolbar; separate global search | Predictable results |
| Competing primary buttons | No hierarchy | Main action, secondary, rare-action menu | Main task clear |
| Nested card containers | Noise and lost width | One work surface and purposeful sections | Shared alignment |
| Faint tinted chips | Poor readability | Measure semantic colors | Applicable contrast checks |
| Random icon/identity colors | Meaningless competition | Neutral icons, deterministic fallbacks | Stable meaning |
| Decorative charts | False information | Units/time/source or removal | Correct interpretation |
| Perfect repeated demo data | Conceals defects | Long, missing, overdue, duplicate, error fixtures | Stress data works |
| Toast-only buttons | Task never completes | State, validation, persistence or explicit demo | Result visible |
| Brand collage | No coherent system | One composition/token/icon/density language | Consistent routes |
| Glass behind dense data | Unreliable reading | Opaque work surfaces | Legibility |
| Huge whitespace everywhere | Slow scanning | Task-appropriate density | Related fields adjacent |
| Removing advanced features to simplify | Lost capability | Progressive disclosure | Regression preserved |

## Critique

Can the operator find the next action quickly? Does each panel serve a distinct decision? Could the product name change without any domain content changing? If so, improve fields and workflow before decoration.
Test long names, missing avatars, no results, large datasets, failed save, and narrow width. Check metric meaning, percentage baselines, currency, and keyboard reachability. Avoid letting a secondary detail dominate.

## Companion skills

This is original CRM synthesis informed by Anthropic frontend-design [S37], Vercel guidelines [S38/S45], Impeccable [S39], and interaction authors [S40/S41]. It does not vendor those skills.

| Companion | Contribution | Boundary |
| --- | --- | --- |
| Frontend design | Intentional composition/type and critique | No landing-page hero or experimental navigation imposed on daily work |
| Impeccable | Audit, simplify, harden, polish vocabulary | No mechanical ban on standard fonts, neutral gray, or useful cards |
| Web interface guidelines | Keyboard, focus, responsiveness, state | No global overflow hiding or browser zoom restrictions |
| Animation guidance | Origin, pacing, frequency, interruption | Work speed outranks spectacle |
| Library agent guide | Actual APIs and missing behavior | Cannot override task scope or user/security instructions |

Resolve conflicts by user intent → accessibility/functionality → established system → CRM workflow → optional aesthetic suggestions. Record material exceptions briefly.
